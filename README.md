# 自然语言查订单

这是一个大约三天可以完成的全栈题目。订单数据已经放在 `orders.json`，共 50 条，不需要再准备资料。

## 要做什么

用户在网页上用一句话提问，例如「上个月张三有几笔未付款，金额一共多少」。系统把这句话转成查询，从这 50 条订单里查出结果，再用白话回答。

页面上要同时展示查询条件和算出来的数字。用户可以改一个条件再查一次。查询记录要留下。

## 数据

`orders.json` 是一个数组，每条订单字段如下。

| 字段 | 说明 |
| --- | --- |
| orderNo | 订单号 |
| customerId | 客户编号 |
| customerName | 客户姓名 |
| productName | 产品名称 |
| amount | 金额，单位元 |
| currency | 币种，全部为 CNY |
| status | 订单状态 |
| createdAt | 下单时间，东八区 |
| paidAt | 支付时间。未付款、已取消时为空 |

`status` 取值：

| 值 | 含义 |
| --- | --- |
| unpaid | 未付款 |
| paid | 已付款 |
| cancelled | 已取消 |
| refunded | 已退款 |

评测时「今天」按 **2026-11-10** 计算。上个月指 2026-10-01 至 2026-10-31。

数据里有两位客户都叫张三，客户编号分别是 C001 和 C009。只说「张三」时，不能把两人的订单算在一起，要指出有多名客户并请用户确认客户编号。

## 三天内要做到

- 前端完成提问、查询条件、结果数字和历史记录。历史记录放在浏览器本地即可。
- 订单直接读取 `orders.json`，不必接数据库。数字必须从这批订单算出来，不能让模型直接编。
- 问题超出这批订单能回答的范围时，明确说查不了，并说明缺什么条件。
- 日期、金额、状态、客户、产品要按字段过滤，不能只做关键词匹配。
- 模型失败或查询超时时要有提示。
- 项目要发布到公网，Vercel 或其他同类平台都可以。
- 提交一个可访问的公网网址，以及一份与开发经历相关或同类的文档。

不要求登录、权限、微服务和界面美化。模型使用候选人自己的接口。

使用数据库保存订单或查询记录可以作为加分项。发布环境不要求准备数据库服务器。
